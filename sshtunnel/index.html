SSHTunnel

macOS 15+

SSHTunnel creates a local HTTP proxy on your Mac. You can use it with any app that lets you configure an HTTP proxy. For example, when you set up the proxy in Firefox, the sites you visit through it see your server’s public IP address.

Download SSHTunnel for Mac
Apple Silicon · arm64 · ZIP

Before you start

The download is for Apple Silicon Macs (M1 or later) running macOS 15 or later. Have your SSH server address, port, username, and password or private SSH key ready. The server must allow TCP forwarding. To verify the server’s identity, use a trusted host key or fingerprint. You can also connect without verification.

Your first connection

  1. Install SSHTunnel

    Download and unzip the archive. Drag SSHTunnel into Applications and open it. The app is ad hoc signed. If macOS asks you to confirm that you want to open it, go to System Settings → Privacy & Security and confirm.

  2. Enter your server and choose a sign-in method

    On the Connection screen, enter your SSH username. Open Settings and fill in SSH server and SSH port. The usual port is 22.

    For password sign-in, keep Username and password selected. To sign in with a key, choose SSH key and select your private key file. Leave the file field blank to use your default key or ssh-agent.

  3. Choose whether to verify the host key

    Verification is on by default. For a new server, obtain its SHA256 fingerprint from your administrator through a trusted channel and paste it into Host key fingerprint. If your Mac already has a trusted key for the server in ~/.ssh/known_hosts, leave the fingerprint and known hosts file fields blank. Click Verify host key. If the fingerprint does not match, check with your administrator whether the key has changed.

    To connect without verification, clear Verify SSH host key in Settings. You can leave the fingerprint and known hosts file fields blank. In this mode, SSHTunnel cannot detect an impostor server, which could receive your password if you use password sign-in.

  4. Connect

    Return to Connection. If you use password sign-in, enter your SSH password. Select Save password in Keychain to reuse it on this Mac. Click Connect and wait for Tunnel connected.

  5. Set up an app that supports an HTTP proxy

    In the app’s network settings, select HTTP proxy. Enter 127.0.0.1 for the address and 18080 for the port. If you changed the port, use the one under Local proxy in SSHTunnel. If the app takes a single address, copy it using the button next to Local proxy.

    Firefox example. Search for “proxy” in the browser settings and open the connection settings. Choose manual proxy configuration, enter the HTTP proxy address and port, enable the same proxy for HTTPS, and save.

  6. Check the connection

    If you configured a browser, open an IP address checker in that browser. If it shows your SSH server’s public IP address, the request went through the tunnel.

Disconnecting

Click Disconnect in SSHTunnel. Apps configured to use the proxy will keep trying to reach it after the tunnel closes. To connect directly again, restore the previous network settings in each app.

Troubleshooting

The server rejected the login. Check your username and sign-in method. If you use an SSH key, make sure the server authorizes the corresponding public key.

The tunnel is connected, but sites won’t load. Compare the address and port in the browser with Local proxy in SSHTunnel. If they match, ask your administrator whether the server allows TCP forwarding.

UDP shows “gateway unavailable.” UDP requires a client that supports CONNECT-UDP over HTTP/1.1 and a BadVPN-compatible udpgw gateway. Disconnect, check the gateway address in Settings (the default is 127.0.0.1:7300 on the SSH server), and reconnect. Regular HTTP and HTTPS requests work independently of this gateway.
